## 强制运行规则

1. 必须先在 Linux 服务器上定位仓库根目录。仓库根目录应同时包含 `README.md`、`requirements.txt`、`rolling_forecast_config.json` 和 `scripts/run_benchmark.py`。确认后进入该目录，所有安装和实验命令都必须从这里执行。不得将用户本地的 `D:\exp` 当作服务器路径。
2. Python 必须严格为 `3.11.15`。运行前执行 `python --version` 验证；不是该版本时，先创建或切换到 Python 3.11.15 的环境，禁止使用其他 Python 版本继续实验。
3. 严格按 README 使用 `python -m pip install --no-deps -r requirements.txt` 安装依赖。
4. 运行前检查模型权重是否存在，并按 README 修改每条命令中的 `checkpoint_path`：只把 `/home/vision_cxy` 替换为 Linux 服务器上的实际仓库根目录，后面的 `pretrained_weights/mae/mae_visualize_vit_base.pth` 保持不变。最终路径必须是有效的 Linux 绝对路径。
5. 运行前使用 `nvidia-smi` 获取当前机器真实、可用的 GPU 卡号和占用情况。不得假设 GPU 一定是 0，也不得把脚本中现有的 `--gpus 0` 原样当作正确配置。
6. 每条 `python ./scripts/run_benchmark.py ...` 命令只能使用一张 GPU。禁止一条任务使用多张卡，禁止任务执行期间跨卡、迁移或由 DataParallel/DDP 自动拆到多张卡。
7. 同一时刻，一张 GPU 只能运行本脚本中的一条实验任务。禁止多个实验脚本或任务并发占用同一张卡。只有当前任务完全结束并释放显存后，下一条任务才可复用该卡。
8. 每条命令的 `--gpus` 参数必须替换成分配给该任务的实际 GPU 卡号。若使用 `CUDA_VISIBLE_DEVICES` 等机制产生了逻辑卡号映射，必须确认并记录物理卡号与框架所见卡号的对应关系，确保 `--gpus` 最终确实指向计划使用的物理 GPU。
9. 如果命令没有 GPU 卡号、现有 `--gpus` 参数不能指定真实卡号，或框架不能保证单任务单卡独占，则必须先修改本仓库的运行框架/调度逻辑，使其能够明确绑定并独占指定 GPU；完成验证前禁止开始正式实验。
10. Traffic 和 Electricity 是特别严格的数据集。对包含 `Traffic.csv` 或 `Electricity.csv` 的每一条命令，必须保证该任务从开始到结束都在同一张 GPU 上运行；不得多卡训练、跨卡执行或中途换卡。不同任务若并发运行，仍必须分别独占不同 GPU。
11. 可以并行运行的任务数不得超过当前实际空闲 GPU 数量，而且每个并行任务必须分配不同卡号。GPU 不足时应排队串行运行，不能让任务共享 GPU。
12. 除 README 要求修改的 `checkpoint_path` 和按实际分配修改的 `--gpus` 外，不得擅自更改命令的模型超参数、数据集、预测长度、保存路径或其他参数。
13. 启动前逐条检查命令；启动后记录每条任务使用的物理 GPU 卡号、命令、开始/结束时间、退出码和日志位置。任务失败时保留错误日志，查明原因后重跑，不能把失败任务当作完成。
